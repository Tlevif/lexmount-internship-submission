01 / 作品说明

Lexmount Real Task Challenge 作品说明 | 更新：2026-10-28

1. 解决什么问题

企业实习招聘分散在不同官网，动态页面、筛选和分页方式各异，逐站查找和比较耗时。本作品聚合北京、上海、广州、深圳、杭州的企业官网实习信息，统一展示计算机技术方向、岗位职责、任职要求、技术栈与来源链接。

2. 云平台参与了什么

Lexmount WebFetch 用于公开招聘入口发现、网页正文提取及 DOM 复用；Lexmount Cloud Browser 用于动态列表、分页、详情页和岗位方向选择。百川证据保留 DOM ID 896894、请求 ID 7e714c3c-c5f8-4232-b4cc-ac37f11377af，云浏览器截图展示6条日常实习。腾讯分页记录保留重复卡片的核验过程。

本次对全库检查缺失详情，复读官方网页及官方公开岗位接口。字节与飞书招聘接口用于读取具体岗位职责和要求；腾讯、阿里、小红书通过 WebFetch 和动态页面读取；百度通过官方列表接口逐页匹配原编号；蚂蚁、Moka 与华为等通过云浏览器核验。华为须选择具体岗位方向后才显示详情，综合岗位仅展示其中已核验的计算机技术方向。

Python 完成字段拆分、稳定标识去重、分类、JSONL 与 SQLite 同步；FastAPI 和网页提供检索、详情与 CSV 导出。人工确定目标和筛选标准，Codex 协助实现采集适配、核对边界岗位、检查原文与更新材料。线上演示使用已保存结果。

4. 发现的问题与验证结果

- 详情漏采：旧页面提示把“未提取”误写成“原站未提供”。本次重新读取缺失字段，处理双语标题、重复小标题、内嵌栏目和动态加载；13条字段不完整记录按用户要求从待处理清单删除。

- 栏目写错：Kimi 推理岗把 Python、C++、CUDA 要求标作岗位职责。按实际原文拆分，并保留来源备注。DeepSeek 旧详情提示迁移，沿官网新链接只提取对应研发方向。

- 分类污染：部门介绍、业务名称及宽泛关键词会把技术岗分到业务类别，也会把业务岗误判成技术。新规则从实际职责中剔除团队介绍，并检查编程及计算机要求；AI工具使用和加分项不单独构成准入依据。

- 动态页面与分页：WebFetch 可能只返回页面壳，云浏览器补足；腾讯重复页用稳定ID去重。历史采集的页面数与当前保留数分开记录。

- 数据装载：JSONL 只按 LF 分行，避免岗位正文中的 Unicode 分隔符破坏记录。当前软件测试 98项通过，3条依赖弃用提示；新增案例覆盖旧标签忽略、营销团队后端、技术美术、非技术移除和中英文技术词识别。

6. 文件用途和运行方法

- results/jobs.jsonl、jobs.json、jobs.csv：筛选后的完整技术岗位结果；CSV含职责、要求、技术栈和官网链接。

- evidence/REBUILD_SUMMARY.json、REBUILD_classification_audit.json：本次全库补采、重新分类及移除记录。

- evidence/full-rebuild/：保留岗位引用的官方接口响应和云端页面原文；evidence/detail-enrichment/为此前待审核补采的历史证据。

- cloud_recheck_20261027.json 与 screenshots/：真实云端运行材料和结果界面。

- workflow.json：说明性执行流程，用于理解各步骤用途。

- runnable_source.zip：最小可运行源码与当前技术岗位数据。解压后按 RUN.md 安装依赖，启动只读 FastAPI；只读演示无需云账号。重新采集需要安装并登录 Lexmount CLI，并继续核验详情。

主要采集期为2026-10-22至23日，2026-10-27补充详情、复核、分类与材料更新。数据库装载时间不作为原站发布时间。原站没有公布发布时间时保持为空。
